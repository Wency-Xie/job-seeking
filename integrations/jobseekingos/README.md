# JobSeekingOS integration contract

The public Skills exchange reviewable files with a local JobSeekingOS workspace. The private workspace and personal data are not part of this repository.

For a job folder, assistants use:

```text
assistants/
  matcher/
    proposal.json  # generated by the Skill; pending review
    draft.json     # retained only after user review
  salary/
    proposal.json  # generated by the Skill; pending review
    draft.json     # retained only after user review
```

The intended product flow is:

1. JobSeekingOS previews the exact job, JD version, and confirmed-profile version that will be read.
2. The user starts a single-job assistant run.
3. The Skill writes `proposal.json`; it does not edit `job.json`.
4. JobSeekingOS displays the proposal as pending and keeps uncertain salary evidence marked for verification.
5. Only an explicit confirmation retains the reviewed fields in `draft.json` or the corresponding local assistant record.

Direct browser-to-Codex invocation is not implemented by these files. A local task runner or an equivalent trusted bridge is required before a JobSeekingOS button can launch a Skill automatically.
