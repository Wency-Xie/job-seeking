# 证据等级与确定性评分

## 核心能力证据

| 等级 | code | 分值 | 判定标准 |
|---|---|---:|---|
| 直接证据 | `direct` | 100 | 已确认档案明确描述同类任务、使用场景和可核对产出 |
| 可迁移证据 | `transferable` | 70 | 相邻场景完成过可迁移任务，但对象、规模或职责不完全相同 |
| 自述或弱证据 | `self_reported` | 30 | 只有技能名、课程、兴趣、自评或缺少产出的概述 |
| 无证据 | `none` | 0 | 已确认档案没有可用证据；不代表候选人不会 |

每条证据包含 `profilePath`、不超过 240 字的 `excerpt`、`reasoning`。引用只能来自已确认档案。

匹配度为各核心能力证据分值按权重加权后的整数四舍五入：

`round(sum(level_score * weight) / 100)`

脚本复算并覆盖输入中的任何模型分数。

## 档案完整度

由准备脚本按六类信息确定性计算：基础身份与教育、目标信息、技能、项目、实习/实践、成果或自我介绍。每类存在非空、可解析内容记 1，完整度为 `round(已填类别 / 6 * 100)`。

完整度只衡量可用于匹配的资料覆盖，不评价候选人质量。低于 60% 时建议固定为“证据不足”。

## 硬门槛覆盖

- `met`：档案明确满足。
- `not_met`：档案明确不满足。
- `unknown`：档案没有足够信息，或 JD 本身不明确。

`not_met` 会覆盖能力分数并输出“暂不推荐”。`unknown` 不自动判失败，但必须进入待确认问题。

## 建议阈值

1. 完整度 `<60` → `evidence_insufficient` / 证据不足。
2. 有硬门槛 `not_met` → `not_recommended` / 暂不推荐。
3. 匹配度 `>=80` → `apply` / 可以投递。
4. 匹配度 `60–79` → `strengthen` / 补强后推荐。
5. 匹配度 `<60` → `not_recommended` / 暂不推荐。
